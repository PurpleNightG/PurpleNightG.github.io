# 紫夜自建 SFU 部署指南

> 适用场景：官网「屏幕共享 → 紫夜自建」模式  
> 组件：**ZLMediaKit（SFU）+ Coturn（TURN）**  
> 实测环境：CentOS 7.6 / Docker / 公网 IP 经 NAT 映射到内网机  
> 本文记录 **2026-07 首次可用部署** 的完整做法，方便下次换服务器照抄。

---

## 1. 架构说明（先搞懂再动手）

```
主播浏览器 ──WHIP──► API 代理(/api/ziye) ──► ZLMediaKit ──WHEP──► 观众浏览器
                          ▲                      ▲
                          │                      └── 媒体 UDP/TCP（直连或 TURN）
                   Vercel/Node 后端
                   
浏览器 ←── STUN（探测公网地址）──► 公共 STUN
浏览器 ←── TURN（打不通时中继）──► Coturn
```

要点：

| 概念 | 说明 |
|------|------|
| **SFU** | 画面**一定**经过 ZLMediaKit，不是主播↔观众 P2P |
| **WHIP / WHEP** | 浏览器推流 / 拉流协议，走 HTTP API |
| **STUN** | 只帮忙探测地址，基本不传媒体 |
| **TURN** | 直连 WebRTC 端口失败时，媒体经 Coturn 中继 |
| **为什么要 API 代理** | 官网是 HTTPS，浏览器不允许网页直连 `http://公网IP:端口`，所以经 `https://api.../api/ziye` 转发 |

## 2. 本次线上实绩（换机时优先照抄这张表）

公网 IP 示例：`160.202.254.36`（换成新机器公网 IP）

### 2.1 外网端口映射（NAT / 安全组）

| 外网端口 | 协议 | 内网（Docker 宿主机） | 用途 |
|----------|------|----------------------|------|
| **10116** | TCP | **10116**（容器 `10116:80`） | HTTP：WHIP/WHEP、ZLM HTTP API |
| **10195** | TCP + UDP | **10195**（容器映射到 ZLM `rtc.port`） | WebRTC 媒体 |
| **10115** | TCP + UDP | **3478**（Coturn） | TURN 信令 |
| **49152–65535** | UDP | 同左 | Coturn **中继端口段**（强烈建议开，否则易丢包→码率塌到几十 K） |

> **常见踩坑**  
> - 误以为「外网 10116 → 内网 8080」。实际 Docker 若是 `10116:80`，NAT 必须是 **10116 → 10116**。  
> - `rtc.port` 必须和外网 WebRTC 端口一致（本次为 **10195**），不能只映射 `10195→8000` 而容器内仍听 8000。

## 3. 服务器准备

### 3.1 系统要求

- Linux（本次为 CentOS 7.6）
- 有公网 IP（或 NAT 能映射上述端口）
- 建议：至少 1 核 2G；上行带宽按推流清晰度预留（1080p60 很吃上行）

### 3.2 上传部署目录

仓库路径：`deploy/ziye-stream/`

```
deploy/ziye-stream/
├── install.sh              # 一键脚本（默认端口偏「内测」；生产请按第 2 节改端口）
├── docker-compose.yml
├── coturn/turnserver.conf
├── zlm/config.ini          # 可选参考；官方镜像也可能用内置默认配置
└── .gitattributes          # 避免 shell 脚本带 CRLF
```

上传到服务器例如：

```bash
# 在本地
scp -r deploy/ziye-stream root@你的服务器IP:/opt/ziye-stream

# 在服务器上：若从 Windows 拷过去，务必去掉 CRLF
cd /opt/ziye-stream
sed -i 's/\r$//' install.sh
chmod +x install.sh
```

## 5. 推荐：生产向手动步骤（与本次一致）

仓库自带 `install.sh` 默认开放 **8080 / 8000 / 3478**，适合直连公网演示。  
**本次因 NAT 策略改成了 10116 / 10195 / 10115**，换机时建议直接按下面做，少踩坑。

### 5.1 改 Coturn 公网 IP

编辑 `coturn/turnserver.conf`：

```conf
listening-port=3478
fingerprint
lt-cred-mech
user=screen123:share666
realm=ziye-stream
no-cli
no-tls
no-dtls
external-ip=你的公网IP
relay-ip=你的公网IP
min-port=49152
max-port=65535
verbose
```

### 5.2 改 docker-compose（示例：对齐外网端口）

将 ZLM HTTP、WebRTC 端口与 NAT 外网口对齐，例如：

```yaml
services:
  zlmediakit:
    image: zlmediakit/zlmediakit:master
    container_name: ziye-zlm
    restart: unless-stopped
    ports:
      - "10116:80"          # HTTP WHIP/WHEP
      - "10195:10195/udp"   # WebRTC —— 容器内 rtc.port 也必须是 10195
      - "10195:10195/tcp"
    volumes:
      - zlm_data:/opt/media/www
      # 若挂载自定义 config.ini，确保其中 [rtc] port=10195、externIP=公网IP

  coturn:
    image: coturn/coturn:4.6.2-r8
    container_name: ziye-coturn
    restart: unless-stopped
    network_mode: host
    command: ["-c", "/etc/coturn/turnserver.conf"]
    volumes:
      - ./coturn/turnserver.conf:/etc/coturn/turnserver.conf:ro

volumes:
  zlm_data:
```

> Coturn 用 `network_mode: host`，宿主机 **3478** 对外映射为 **10115**。

### 5.3 启动

```bash
cd /opt/ziye-stream
docker compose up -d
# 或旧版：docker-compose up -d

docker ps
docker logs ziye-zlm --tail 50
docker logs ziye-coturn --tail 50
```

### 5.4 设置 ZLM 公网 IP（必做）

从日志取出运行中的 `api.secret`（镜像可能随机改过），然后：

```bash
SECRET=$(docker logs ziye-zlm 2>&1 | grep 'modified it to' | tail -1 | sed 's/.*modified it to: \([^,]*\).*/\1/' | tr -d ' ')
# 若为空，用镜像默认 secret（以实际日志为准）

curl -g "http://127.0.0.1:10116/index/api/setServerConfig?secret=${SECRET}&rtc.externIP=你的公网IP&rtc.port=10195&rtc.tcpPort=10195"
```

验证：

```bash
curl -s "http://127.0.0.1:10116/index/api/getServerConfig?secret=${SECRET}" | head
curl -s "http://127.0.0.1:10116/index/api/version"
```

> WHIP/WHEP **一般不需要**带 secret；浏览器报 `Please login first` 多半是误走了需登录的管理 API，检查路径是否为 `/index/api/whip`、`/index/api/whep`。

### 5.4 防火墙 / 安全组

宿主机 `firewalld`（若开启）：

```bash
firewall-cmd --permanent --add-port=10116/tcp
firewall-cmd --permanent --add-port=10195/tcp
firewall-cmd --permanent --add-port=10195/udp
firewall-cmd --permanent --add-port=3478/tcp
firewall-cmd --permanent --add-port=3478/udp
firewall-cmd --permanent --add-port=49152-65535/udp
firewall-cmd --reload
```

云厂商安全组 / 上级 NAT：**放行第 2.1 节全部外网端口**。

## 6. 官网侧配置（换 IP 必改）

### 6.1 Vercel 后端

1. 项目根目录选 `server`  
2. 部署包含 `routes/ziye.js`、`routes/room.js` 的最新代码  
3. 环境变量：`ZIYE_UPSTREAM_URL=http://新公网IP:10116`  
4. 确认 `api.sh01.eu.org`（或你的 API 域）已绑到该 Vercel 项目  

代理逻辑：`/api/ziye/*` → `ZIYE_UPSTREAM_URL/*`（WHIP/WHEP SDP 中转）。

### 6.2 GitHub Pages 前端

`.github/workflows/deploy.yml` 构建环境变量需指向新 TURN 主机：

```yaml
VITE_ZIYE_SERVER_URL: https://api.sh01.eu.org/api/ziye
VITE_ZIYE_TURN_HOST: 新公网IP
VITE_ZIYE_TURN_PORT: '10115'
VITE_ZIYE_USE_TURN: 'true'
```

推 `main` 后 Actions 自动部署静态站。

### 6.3 前后端权限相关（流媒体无关，但上线要齐）

- 房间登记 mode=`ziye`，观众输入房间号可自动识别模式  
- 发起紫夜共享：管理员 / 授权助教可直接用；普通学员需申请审批（`rtc_permissions.mode` 含 `ziye`）

## 7. 流媒体路径约定（勿改除非同步改前端）

前端 WHIP / WHEP：

```
推流: POST {ZIYE_SERVER}/index/api/whip?app=live&stream=screen-{房间号}
拉流: POST {ZIYE_SERVER}/index/api/whep?app=live&stream=screen-{房间号}
```

房间号为 6 位大写码。线上 `ZIYE_SERVER` = `https://api.sh01.eu.org/api/ziye`。

ICE（前端 `ScreenShare.tsx`）：

- STUN：Google / QQ 公共  
- TURN：`turn:公网IP:10115`，账号密码见上文  
- `VITE_ZIYE_USE_TURN=false` 时去掉 TURN，只直连 ZLM；部分网络会无画面

## 8. 验收清单

在服务器上：

```bash
docker ps | grep ziye
curl -s http://127.0.0.1:10116/index/api/version
ss -tulnp | grep -E '10116|10195|3478'
```

在浏览器：

1. 管理员选 **紫夜自建** → 开始共享 → 能出本地预览  
2. 另一账号输入房间号 → **不必选手动模式** → 能看画面  
3. 看延迟/帧率；上行不应在十几秒后塌到几十 Kbps  

可选：Chrome 打开 `chrome://webrtc-internals`，看候选是 `srflx`（直连）还是 `relay`（TURN）。长期 `relay` 且画质不稳 → 优先补 `49152–65535/UDP`。

## 9. 常见故障（本次踩过的）

| 现象 | 原因 / 处理 |
|------|-------------|
| `install.sh` 语法错 / `$'\r'` | Windows CRLF → `sed -i 's/\r$//' *.sh` |
| 无 Docker / compose | 见第 4 节 |
| Docker Hub 超时 | 镜像加速 + 国内 pull 源 |
| ZLM `Restarting` | 3478 被占用或配置冲突；本次把 ZLM 内置 ICE 挪开，3478 留给 Coturn |
| WHIP `Please login first` | 别走管理 API；确认 whip/whep 路径；一般不必带 secret |
| HTTPS 页 `Failed to fetch` | 必须走同源 `/api/ziye` 代理，不要让浏览器直连 `http://IP` |
| 观众长时间无画面 | 查 NAT、TURN；**勿随意关 TURN** 除非确认直连必通 |
| 刚连上几秒正常，上行从 ~1M 掉到 ~30K | 多半是拥塞控制误判或 TURN 中继端口不全，**不是 STUN 导致**；补中继 UDP 段、检查丢包 |
| 外网 IP 开了口仍不通 | 核对「外网口 → 内网口」是否与 Docker `ports` **逐字一致** |
